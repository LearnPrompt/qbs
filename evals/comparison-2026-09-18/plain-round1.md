## 三、交给运营的共享表格与执行边界

运营已有排期经验，可以完整负责维护、催办和风险上报。你保留内容验收与发布日期决定权。A、B 分别绑定实际负责写手即可；其余写手不自动计入剪辑产能。

每条视频一行，至少保留这些字段：

| 字段 | 填写要求 |
|---|---|
| 视频及责任人 | 写手、剪辑、运营、内容验收人分别明确 |
| 原定节点 | 原交稿、审核、发布日期与时间；保留原值 |
| 当前批准节点 | 有明确批准才更新，附你的确认记录 |
| 最新预计时间 | 责任人给出的预测，可以变化，但不能替代批准时间 |
| 实际完成时间 | 按实际交付填写，附脚本、素材或成片链接及版本 |
| 状态与风险 | 待交付、剪辑中、待审核、修改中、可发布、已发布；记录阻塞原因及影响 |
| 催办与上报记录 | 提醒时间、风险发现时间、上报时间、待你决定的事项 |
| 变更记录 | 旧值、新值、原因、提出人、批准人、批准时间及记录链接 |

执行时按以下标准交接：

1. **方案未获确认前：** A、B 标记“排期待确认”，保留原发布日期，记录资源冲突及上述备选方案，不把备选时间写成已批准时间。
2. **写手交付时：** 运营核对脚本、素材链接、版本及已有内容审核记录是否齐全，登记实际交付时间；内容判断仍由你负责。
3. **剪辑交付时：** 运营确认有可播放的成片链接，按确认后的审核时间交给你；不能把“预计剪完”当作实际就绪。
4. **你审核后：** 登记审核结论和修改清单，剪辑处理并导出。涉及内容变动或未解决问题，交回你确认；运营不自行认定内容合格。
5. **发布前：** 确认内容验收结论、修改完成状态、最终导出文件和批准的发布时间齐全。发布后记录实际时间与链接。

风险上报沿用“发现后半小时内”的标准，临近关键节点时立即报。每次上报写清：哪条内容、原节点、最新预计、影响、可选处理及最晚需要决定的时间。你回复“知道了”，只表示收到风险；涉及改期，必须另有明确决定。

运营的验收看她能控制的事项：表格是否完整准确、是否按约提醒、风险是否及时上报、改期是否有明确批准、交付记录是否闭环。作品质量由你验收，写手和剪辑的迟交分别记录，不能用最终结果替代对运营履职的判断。

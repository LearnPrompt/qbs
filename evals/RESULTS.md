## 做了什么

两位独立 Codex 子代理读取实际 Skill 后执行模拟任务，未获得预期答案，未读取本目录的结果。子代理继承本任务模型配置，未单独记录精确模型版本或采样参数。主代理逐项核对实际产物；**不是盲评，也不是多轮稳定性统计**。

三个父 Skill 测试（第三个在同一个独立会话继续执行）和三个书籍子 Skill 测试，共六个输入，每个一次。没有联网、没有真实任务系统写入或消息发送。父 Skill 的新书生成测试确实在隔离目录制作了五个文件，产物保存在本目录。

## 文件与安装检查

`python3 scripts/validate.py` 检查两份正式 Skill 的入口、独立相对引用、登记书籍和封面链接。两份 Skill 还分别通过 Codex skill-creator 的 frontmatter 与命名检查。

`python3 -m unittest discover -s tests -v` 共19项：父/子独立安装、整体安装后哈希读回、dry-run 不写入、冲突前置停止、未知路径拒绝、符号链接边界、暂存失败、并发用户文件保护、仅清理空预留目录，以及缺来源/跨包依赖/缺封面/越界路径/重复目录条目/未闭合元数据/正文伪装元数据的拒绝。

发布前审查发现并修复两处问题：不完整 frontmatter 曾会错误通过；整目录回滚可能删除并发新增的用户文件。现在只以完整元数据块校验，每个包暂存后提交，异常时保留用户数据；新增四项回归测试。

这些测试验证包装和文件行为，不验证管理知识的真伪或模型稳定性。父 Skill 和正式书籍子 Skill 已在 macOS 的 Codex 用户目录完成安装并读回一致；app-server `skills/list` 强制刷新后两者均为 `enabled: true`。此结果证明本机发现，不代替新会话任务执行或其他宿主的验证。

书籍封面来自出版社，已在未登录的 GitHub 公开仓库与书籍页核对：图片加载尺寸292×450，页面可见真实书名、作者及封面。离线脚本只检查引用与登记一致，无法保证第三方链接永久可用。

## 没有做什么

- 没有完成全书阅读；当前书籍子 Skill 仅为公开序言启发的场景应用。
- 上述首版测试没有进行三组对照；后续已补充[一题、三组、各两轮的小型对照](comparison-2026-09-18/REPORT.md)，未证明优于直接对话，仍没有多题重复的稳定性证据。
- 没有跨模型、多次重复或真实团队效率实验。
- 没有验证所有支持 Agent Skills 的宿主。文件复制成功与模型发现、实际调用是不同证据。

正式书籍条目状态为 `simulated`，不是 `field-tested`。

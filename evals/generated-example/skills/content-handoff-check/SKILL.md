# 内容交接检查

把一份交接记录变成可审阅的完整性检查和处理建议。本 Skill 可独立调用，所需参考资料均在自身目录内，不依赖 QBS 父 Skill。

## 何时使用

内容材料即将交给下一位负责人，或接收方发现缺项，需要决定补齐后开工还是有条件先处理部分内容。

本 Skill 只检查交接信息和材料齐全情况，不替代内容质量、版权或发布审核，也不提供全书方法。

## 必要输入

- 交付物及约定应包含的材料或清单；材料链接可由用户提供。
- 原负责人、下一位负责人，以及交接的约定时间。
- 实际已收到的材料及接收方确认记录；未提供则标为待核实。
- 如需紧急部分开工：紧急原因、拟先处理的部分、缺项影响及双方确认记录。

信息不足时，先输出带缺口的草稿，仅追问会改变完整性判断或开工决定的内容。不得编造材料、人员、时间或确认。需要比较时间时，日期或时区有歧义则先标明待确认。

## 判断与行动

1. 记录交付物、原负责人、下一位负责人和约定时间，保留已有约定；缺失的信息明确留空待补。
2. 将约定清单与已收到材料逐项比对。只有文件存在或发送方说已交付，不能代替接收方对材料齐全的确认。
3. 材料齐全且接收方已确认时，可建议进入制作。清单或确认缺失时，结论为待核实，不自动认定完整。
4. 有缺项时，列出每项缺口、已知影响、负责补齐的原负责人；未知影响标为待确认。默认建议补齐并由接收方重新确认后再进入制作。
5. 紧急情况需要部分开工时，先划定不受缺项影响的部分及其依据。只有交出方与接收方均确认后，才可建议按该范围部分开工；同时记录剩余缺项、残余风险和需补齐事项。影响尚不清楚、双方未确认或已有明确反对时，不将部分开工写成获批安排。
6. 输出交接检查结论、依据、缺项与下一步。建议、双方已确认的安排和实际执行状态分别表达。

## 交付与验收

可使用 [交接检查模板](references/handoff-template.md)，或直接以表格输出。

产物应使用户能够检查：

- 谁向谁交接什么，约定时间是什么。
- 材料是否齐全，依据是什么，接收方是否确认。
- 缺什么、影响什么、由谁补齐。
- 若紧急部分开工，范围为何不受缺项影响、双方是否确认、残余风险是什么。

结论使用「可建议进入制作」「补齐后再确认」「待核实」或「双方已确认的部分开工建议」，并附依据。这些是建议状态；没有实际执行记录，不能声称已经开工、补齐或完成交接。

# 实验后、修复前诊断

experiments.log 的实测与 H2 全部预测一致。直接切片 [2:4] 和新 key 都返回 [2,3]，同 key 返回 [0,1]。offset=2、limit=2 全部在长度 6 的范围内，仍失败，排除“必须越界才失败”的解释。清空本地缓存后恢复 [2,3]，支持状态依赖，也能解释进程重启后首次调用恢复的机制；未实际执行或验证线上重启。

因果：首次调用把一次切片存到 _cache[key]；之后相同 key 命中，使控制流跳过切片，忽略新的 offset、limit、rows；最终 list(_cache[key]) 只复制旧容器，不重新计算当前结果。改变参数和改变数据是同一控制流缺陷的两个触发方式。

错误性：违反用户确认的“每次返回当前 rows 对应切片”。即使改用 (key, offset, limit) 缓存，rows 更新后仍旧失效。没有数据版本或可靠失效机制的需求，直接按当前输入切片是最小且覆盖相关输入的修复，保留 key 参数兼容原调用。

修复前回归：8 项测试，5 项失败、3 项通过。失败为换页、limit、替换 rows、原地修改 rows、空结果后同 key 的尾页。相关成功是首次默认页、tuple 转 list、返回容器隔离。

修复后预测：相同的 8 项测试应全部通过。若仍失败，返回诊断；不修改已有正确断言。

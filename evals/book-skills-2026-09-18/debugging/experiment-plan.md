# 运行前记录

预期依据：用户约定每次返回当前 rows[offset:offset + limit] 对应的 list；offset >= 0、limit > 0，rows 可在调用之间变化。

H1（用户猜测）：切片越界导致旧结果。若是切片本身错误，同样 rows、offset、limit 的直接切片或首次调用也应异常；完全在边界内的换页不足以触发越界。比较直接切片、旧 key 与新 key 的调用。

H2（代码支持的候选）：只按 key 保存首次切片，后续命中绕过新参数和 rows。若成立，同 key 换页、改 limit、换 rows、原地改 rows 都返回首次值；换新 key 或重置模块状态后恢复当前切片。若同 key 后续调用正确，则削弱这一解释。

- 同 key limit=3 时实际仍为 [0,1]，正确值为 [0,1,2]。
- 同 key 换成 [10,11,12] 或原列表第一个元素改成 99 时，实际仍为 [0,1]；分别应为 [10,11]、[99,1]。
